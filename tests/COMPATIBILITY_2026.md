```sh

```

Repeat for php80, php81, php82, php83, php84 and php85. The pinned PHPUnit 9.6.38 checksum is verified. Their original ordinary case identities require the precise documented InvalidArgumentException, with no native diagnostic expected or hidden. Scalars and stringable objects retain native string conversion.

The original 243-case complete initial matrix was captured before production edits. A later replay on a detached checkout of the exact source baseline, using the final strict harness, also retains every native stdout/stderr/status capture and confirms unchanged production bytes. Focused regressions retain the established intended behavior for settings, caches, optional components, legacy forwarding, UTF-8 text and extraction. Active source hashes now describe the rebuilt distributed artifact, while `BASELINE_SOURCE_INVENTORY.json` retains the source baseline's original inventory.

Two earlier fixtures required correction. The diagnostic sentinel expected an exception in the passing process, which is incompatible with durable unexpected-diagnostic detection; it now verifies a failing owned process. The oversized-license-URL case required a ciphertext for a payload larger than the actual shipped 4096-bit RSA key permits. Independent PHP 7.4 and 8.5 probes confirm the PKCS#1 v1.5 limit is 501 input bytes: 501 encrypts to 512 bytes, while 502 and 1100 fail. The source now rejects such payloads before encryption and emits no broken pixel; the regression requires two false returns and an empty footer. Ordinary and development positive pixel cases retain their ciphertext/footer assertions. No wire format, key, licensing constant or generated JavaScript changed.

Settings parsing delegates to native unserialize without restricting valid objects, references or noncanonical syntax. A local handler recognizes only enumerated native malformed-input diagnostics at the exact parser call, restores the previous handler, and forwards every other diagnostic with the runtime's original argument list. Object hydration exceptions and diagnostics remain visible, including deferred callbacks during malformed-input cleanup. A lexical pass rewrites only native legacy escaped-string tokens, preserving opaque payloads, valid signed object counts and unrecognized remainders for the native parser. Public settings shapes, ArrayAccess reads, references and base64/native serialization are preserved. Existing native values followed by trailing unused bytes retain their historical parsed prefix; out-of-range integer literals retain the native clamped result rather than discarding nested settings. Both accepted-value warnings are handled only at the exact native call, and callback diagnostics still reject validation.

Cache keys retain zero-valued components and escape separators/backslashes uniformly for scalar and compound inputs to prevent introduced aliases. This changes hashes for separator-containing scalar names and zero/special compound names; existing cache files are disposable and are not rewritten. Stored payload serialization is unchanged. Normal single keys and ordinary compound keys keep their hashes. Review should explicitly consider this cache invalidation behavior.

The legacy extensible BaseMcp retains its existing property declarations. Its narrowly scoped AllowDynamicProperties attribute preserves the original bare-controller pagination contract without adding a public data declaration that would break existing protected/private or magic consumers. Six actual original-PHP-7.4 consumer cases match the candidate on all seven runtimes. Actual direct and extension-free extraction-entry regressions reject scoped root/container links before resolving or cleaning their targets; direct cleanup handles the link itself. Startup, provider, caught native, hydration and timed-out child diagnostics remain fail conditions, with complete retained child streams and status.

Passing unit tests do not establish full EE installation, SQL/database behavior, HTTP licensing delivery, complete historical EE integration, Windows extraction, or live-site compatibility. No coverage-completion claim is made.
